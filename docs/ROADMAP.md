### 1 CI, signing and versioning
Done (sessions 2 to 4; CI run 3 green, not run on a device):
- Toolchain pinned (decision 12); wrapper and root Gradle files.
- `app` module without engine; `versionName`/`versionCode` from `version.properties`; ABI splits (arm64, universal).
- `build-android.yml`: debug APKs on push and pull request.
- `verification-bootstrap.yml`: manual, writes dependency checksums.
- Provisional, pending owner approval: application id `io.github.g_c_3.ardour`, minSdk 26, SDK 36.

Remaining:
- Owner runs `verification-bootstrap.yml`, downloads the artifact, commits `gradle/verification-metadata.xml`; then CI fails if it is missing.
- Fix any failing step the owner pastes.
- Release workflow: signed APKs on tag `vX.Y.Z`, SHA-256 in notes.
- Keystore (decision 13): open. Method to choose: (a) one-off workflow that stores the key as a repository secret through a fine-grained token kept as a secret, plus an encrypted backup saved outside GitHub; (b) key generated by a trusted tool the owner has.
- Owner decision: app license.
- DP0: install a debug APK; the app opens and shows the name "Ardour".
