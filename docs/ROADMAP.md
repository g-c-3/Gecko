### 1 CI, signing and versioning
Done (session 2):
- Toolchain verified and pinned (decision 12).
- Wrapper files, `gradle/libs.versions.toml`, `settings.gradle.kts`, `build.gradle.kts`, `gradle.properties`.

Remaining:
- Minimal `app` module that builds (no engine). Needs owner approval of the application id; proposed `io.github.g_c_3.ardour`, fixed once released.
- `versionName` and `versionCode` from `version.properties` (decision 4); ABI splits for arm64 and universal. Verify the AGP variant-output API against AGP 9.5 documentation first.
- `build-android.yml`: build and upload debug APKs on push; signed release on tag `vX.Y.Z`; SHA-256 in notes; actions pinned by SHA.
- Verification metadata: manual workflow writes `verification-metadata.xml` as an artifact (public checksums only); owner commits it. Then CI fails if the file is missing.
- Keystore (decision 13): open. A keystore cannot be made on the phone without a terminal, and CI output is public. Method to choose with the owner, one of: (a) a one-off workflow that generates the key and stores it as a repository secret through a fine-grained token kept as a secret, with an encrypted backup the owner saves outside GitHub; (b) a key generated by a trusted tool the owner already has.
- Owner decision: app license.
- Risk: nothing here has run through CI yet.
